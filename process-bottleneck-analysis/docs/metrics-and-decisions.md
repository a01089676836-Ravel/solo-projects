# 지표 정의·선택 기준

## 모집단과 비교 코호트

- 원본 단위: 구매 문서와 항목의 조합인 case ID.
- 유형: `3-way match, invoice before GR`.
- 전체 trace에서 Create Purchase Order Item, Record Goods Receipt, Record Invoice Receipt, Clear Invoice가 각각 정확히 1개.
- Cancel Goods Receipt, Cancel Invoice Receipt, Delete Purchase Order Item이 없어야 함.
- 생성 ≤ 입고 ≤ 지급, 생성 ≤ 송장 접수 ≤ 지급이어야 함. 송장과 입고 사이의 순서는 제한하지 않음.
- 같은 활동·같은 시각 기록이 반복되면 중복 후보로 제외. 서로 다른 실제 작업일 수도 있어 원본에서 삭제하지 않음.
- 구간 계산에는 생성 시각 이상, 지급 시각 이하의 이벤트만 사용. 밖의 이벤트 수는 별도 기록.

위 조건은 단순 비교 사례의 정의이며 실제 계약 정합성·금액 대사·완납 여부 검사가 아님.

## 지표

| 이름 | 정의 및 분모 |
|---|---|
| cycle_days | (지급 기록 시각 − 구매 항목 생성 시각) / 86,400초 |
| 중앙값·P90 | 코호트 사례별 cycle_days의 선형 보간 분위수(type 7) |
| 인접 전이 | UTC 정렬 사례 안에서 바로 이어지는 두 이벤트 |
| 전이 발생 수 | 해당 인접 전이가 발생한 횟수. 동일 사례에서 여러 번 가능 |
| 전이 사례 수 | 해당 전이를 포함하는 고유 case ID 수 |
| 전이 경과시간 | 인접한 두 이벤트의 시간 차이. 대기·작업시간 분리 불가 |
| 누적 사례·일 | 모든 해당 전이 경과시간 합계. 노동시간·비용·공장 가동일 아님 |
| 가격 변경 기록 비율 | 생성~지급 구간에 Change Price가 한 번 이상 있는 코호트 사례 / 전체 코호트 사례 |
| 대표 경로 | 생성~지급 구간 활동 순서의 최빈값. 반복 활동 포함 |
| 제외 사유 수 | 한 사례에 여러 조건 적용 가능. 합계는 제외 사례 수와 다를 수 있음 |

## 조사 후보와 시나리오

최소 30개 사례에 나타나는 양의 경과시간 구간 중 누적 사례·일 최대 구간을 선택. 30은 탐색용 설계값이며 통계 검정 임계값이 아님.

각 사례의 가정 시간 = 원래 cycle_days − 선택 구간의 인접 경과시간 합 × 단축 비율.

선택 구간이 없는 사례는 그대로 포함. 조정된 사례 시간 분포에서 전체 중앙값·P90을 다시 계산. 단축 가정은 0/10/20/30%. 이 모델에는 자원 경쟁·계약 지급기한·배치 처리·업무 변경에 따른 연쇄효과가 없음.

## 선택한 접근과 대안

| 선택 | 대안 | 현재 선택 이유 / 바꿀 조건 |
|---|---|---|
| 공식 XES 전체 | 다른 사람의 CSV·앞부분 표본 | 원본 해시와 전체 수를 검증할 수 있음. 규모가 커지면 사례 단위 층화 표본 고려 |
| Python 표준 라이브러리·SQLite | pandas·PM4Py | 의존성 없이 재현하고 계산 규칙을 확인하기 쉬움. 프로세스 모델 정합성·복잡한 패턴 발견이 필요하면 PM4Py 추가 |
| 직접 전이·빈도·시간 | Petri net·예측 모델 | 이번 질문은 관측 흐름과 병목 후보 찾기. 자동 규칙 위반·잔여시간 예측은 별도 검증 필요 |
| 구조가 단순한 코호트 | 전체 유형 혼합 | 부분 지급·반복 처리의 의미를 섣불리 단정하지 않음. 금액 매칭이 구현되면 복잡한 사례로 확대 |
| 누적 경과시간 기준 | 최대값·중앙값만 사용 | 발생 규모와 시간 함께 반영. 계약조건상 줄일 수 없으면 예외 처리 등 다른 후보로 변경 |
| 가정 기반 민감도 | 인과 효과·실제 절감 주장 | 개입 전후 실험 데이터가 없음. 현장 비교 설계와 실제 측정 후 효과 주장 가능 |

## 관측 한계

기간 말 미지급 사례가 빠지고 단순 처리 사례만 남으므로 선택 편향이 있음. 공급업체·회사·금액·제품 차이에 대한 인과적 통제를 하지 않음. 가격 변경 사례의 처리시간이 길더라도 가격 변경이 원인이라고 결론낼 수 없음. 동시각 순서는 원본 기록 관례에 영향을 받음. 금액·계약 지급조건·지급 완료 상태를 검증하지 않았으므로 법적·회계적 위반으로 분류하지 않음.
