# 실제 작업 경로와 증거 — 2026-09-25

## 목표와 완료 기준

사용자가 선택한 업무 로그 기반 병목 분석을 실제 데이터로 실행 가능한 로컬 MVP로 만든다. 원본 출처와 전체 수 확인, 비교 코호트의 설명, 원본 사례 추적, 가정 기반 개선 비교, 자동 검증, 실행 안내를 완료 기준으로 삼았다. 현장 성과나 상용 배포는 목표에 포함하지 않았다.

## 실제 실행 경로

1. 공식 포털·대회 페이지 웹 조회는 403/timeout으로 실패했다. 공식 메타데이터 API `https://api.figshare.com/v2/articles/12715853`는 curl로 조회 성공했다.
2. API가 가리키는 공식 원본 URL `https://ndownloader.figshare.com/files/24072995`에서 전체 XES를 다운로드했다. 제3자 가공 CSV는 사용하지 않았다.
3. Python 3.14.6을 확인했다. 일부 도구 셸에서 `python` 단축 명령을 찾지 못해 확인된 실행 파일 절대 경로를 사용했다.
4. 파일 크기·MD5를 검사한 뒤 스트리밍 XML 변환을 실행했다. 전체 count를 출처의 251,734 / 1,595,923과 대조했다. 기존 원본 순서에서 시간 역전 사례는 0건이었다.
5. 같은 활동·같은 시각의 추가 이벤트 후보 180,913개를 기록했다. 이를 원본 중복 오류로 확정하지 않고 그대로 보존했다. 전체 동시각 인접 전이는 233,463개다. 이 수치의 단위는 사례 수가 아닌 이벤트/전이 수다.
6. 비교 코호트 선정과 전이·시간 분석을 실행했다. 원본 계보는 원본 해시 → 사례 ID → 정렬 후 seq·원본 source_order → 활동·UTC 시각 → 보고서 전이로 이어진다.
7. 별도 SQL로 코호트 ID를 재선정하고 중앙값·구간 시간 합계·출처 연결을 확인했다. 보고서의 모든 근거 전이 990개도 원본 변환 DB와 대조했다.
8. 한국어 웹 화면과 읽기 전용 API를 구현하고 로직·HTTP·DOM 대역 테스트를 수행했다.
9. `computer-use` 스킬을 읽고 브라우저 도구를 시도했다. IAB 사용 불가, 브라우저 목록 빈 배열을 확인했다. 실제 화면 검수는 완료하지 못했다.

## 실행 중 발견·수정한 문제

- HTTP 테스트의 임시 SQLite 파일이 닫히지 않아 Windows에서 정리 단계가 실패했다. 테스트 fixture 연결을 명시적으로 닫고 HTTP 오류 응답 객체도 닫도록 수정했다. 실제 서버는 이미 finally에서 연결을 닫도록 구현되어 있었다.
- 검증 실행기가 Node의 체크 표시 문자를 Windows cp949 출력으로 내보낼 때 실패했다. 표준출력 UTF-8 설정을 추가하고 실제 전체 검증을 다시 수행했다.
- 최종 Python 17개, Node 3개, 독립 검사 11개가 모두 통과했다. 실패를 숨기지 않고 이 기록에 원인과 수정 내용을 남겼다.

## 실행 결과를 다시 확인하는 방법

- `python verify_project.py`: 자동 검사와 독립 SQL 검사, 실제 출력·종료 코드 보존.
- `reports/analysis.json`: 지표 정의에 따른 전체 수치와 전이별 근거.
- `reports/cohort-membership.json`: 개별 사례의 포함·제외 사유.
- `reports/verification.json`: 검사별 true/false와 생성 시각.
- `reports/test-results.json`: 실행한 명령, 종료 코드, 시각 검수 한계.

변환 기록의 code_sha256은 최초 변환 당시 pipeline.py 해시이며 분석 결과의 code_sha256은 해당 분석 당시 해시다. 최초 변환 이후 분석의 제외 사유 표시를 묶는 코드를 추가했다. 입력 스키마·원본·변환 규칙은 유지했다. 현재 파일로 전체를 다시 만들려면 `python pipeline.py all`을 실행한다.

## 사용자가 검토할 핵심 판단

왜 가장 긴 구간이 반드시 개선 우선순위 1위는 아닌지, 정상 지급조건이 확인되면 추천을 어떻게 바꿀지 검토한다. 사용자가 이 질문에 답했거나 이해를 입증했다고 아직 기록하지 않는다.

## 후속 실제 브라우저 검증 완료

사용자가 Playwright 검증을 명시적으로 요청하여 Google Chrome 153 headless로 확인했다. 기존 CUA 연결 실패와 별개로, 실제 렌더링 및 검색·사례 선택·시나리오 변경 10개 검사가 통과했다. 검색 공백·이전 요청의 오류·재시도 상태·중복 번호를 수정했고 PNG 4개를 시각 검토했다. 최신 증거는 reports/browser/results.json과 reports/browser/검증결과.md에 있다. 이전의 브라우저 미검증 기록은 최초 실행 당시 상태다.
