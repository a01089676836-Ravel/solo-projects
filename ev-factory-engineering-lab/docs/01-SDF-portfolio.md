# 프로젝트 01 · SDF 공정 데이터 품질·불량 위험 분석

## 한 문장

전동화 부품의 공정 이력을 검증해 저장하고, 최종검사 이전 측정값으로 추가 점검 후보를 찾는 재현 가능한 분석 파이프라인.

## 보여줄 역량

| 영역 | 구현 | 근거 |
|---|---|---|
| 데이터 엔지니어링 기초 | 제품·공정 키, 결측/시간/중복 점유 검사, CSV→SQLite | factorylab/data.py, output/validation.json |
| SQL·이력 분석 | 일자·사양별 품질, 공정별 대기, 개체 단위 추적 | docs/queries.sql, 대시보드 이력 조회 |
| 통계·머신러닝 | 학습 전처리, 시간순 분할, 가중 로지스틱, 검증 임계값 | factorylab/modeling.py |
| 평가·운영 판단 | AP/Recall/Precision, 검토율, 혼동행렬, 블록 부트스트랩 | output/model_metrics.json |
| 엣지 확장 | JSON 모델·표준 라이브러리 추론·입력 거부·점수 일치 검증 | factorylab/edge.py, tests/test_project.py |

이 표는 주어진 직무명과 제조 데이터 문제를 연결한 프로젝트 설계입니다. 해당 채용 공고의 세부 문항을 모두 확인한 요구사항 대조표는 아닙니다.

## 3분 시연 순서

1. 생산 현황에서 일자 25, 사양 B를 선택하여 불합격률과 리드타임을 확인합니다.
2. `D25-U0001`을 조회하여 제품 ID 하나로 네 공정과 품질 결과가 연결됨을 보여줍니다.
3. SDF 탭의 학습/검증/시험 경계를 설명합니다. EOL 결과가 입력에 없음을 코드에서 확인합니다.
4. AP만 보여주지 않고 놓친 불량과 검토율을 함께 제시합니다.
5. 임계값 슬라이더는 사후 탐색임을 밝히고 저장된 임계값과 구분합니다.
6. 경량 추론 예제를 실행한 뒤, 필수 값을 누락했을 때 점수 대신 검토 상태가 나오는 것을 보여줍니다.

## 결과 기록

현재 실제 실행 수치는 `output/RESULTS.md`와 `output/model_metrics.json`에 있습니다. 검토율이 용량 30%를 넘는다면 **배포 준비가 되었다고 주장하지 않고** 검토 대상 축소, 비용 정의 재검토, 추가 데이터 확보 등의 후속 과제로 설명합니다. 시험 데이터로 새 임계값을 고르면 새 시험 기간이 필요합니다.

## 자기소개서용 문장 초안

아래 문장은 본인이 코드를 실행·수정하고 결과를 설명할 수 있게 된 범위에서 사용합니다.

> 전동화 부품 조립을 가정한 모의 데이터 프로젝트에서 공정 이력의 누락과 순서 오류를 검증하고, 제품별 데이터를 SQLite에 연결하는 흐름을 학습했습니다. 불량 위험 분석에서는 시간순으로 학습·검증·시험 구간을 분리하고 검증 구간에서 임계값을 선택했습니다. Recall뿐 아니라 추가 점검 부담과 놓친 불량을 함께 확인하며, 분석 결과를 운영 조건과 연결해 설명하는 데 집중했습니다. 결과는 모의 데이터에 한정되며 실제 공정 성과로 확대하지 않았습니다.

AI 지원 범위와 자신의 변경사항을 `docs/worklog-template.md`에 기록합니다. 아직 수행하지 않은 Jetson 검증이나 현장 적용을 완료 경험으로 적지 않습니다.
