# 이 결과물을 본인의 프로젝트로 발전시키는 4주 계획

현재 전달물은 실행 가능한 AI 지원 초안입니다. 이미 완료된 개인 실무 경험으로 취급하지 말고, 아래 순서로 실행·수정·설명 능력을 확보합니다. 기간은 학습 계획이며 수료 실적이 아닙니다.

| 주차 | 본인이 수행할 일 | 남길 증거 |
|---|---|---|
| 1주 | 대시보드와 SQL 실행, 한 부품의 네 공정 이력을 손으로 확인, 불량/완료량 분모 설명 | SQL 결과, 이력 해석, 데이터 사전 수정 |
| 2주 | 시간순 분할·누수·혼동행렬 학습, 결측/중복 샘플을 주입해 오류 확인, 고정 모델 결과 설명 | 실패 재현 로그, 모델 평가 메모 |
| 3주 | 유한 버퍼 또는 장비 고장 중 하나를 실제 코드에 추가, 기존 대안의 효과 변화 비교 | 변경 diff, 새 시드 실험, 실패한 가설 |
| 4주 | Jetson 경량 추론 실행, 입력 리플레이, 장치/버전/부하 조건을 기록하고 3분 시연 | 기기 명령 결과, 지연시간 원시 로그, 시연 영상 |

## 면접에서 설명할 질문

1. 왜 무작위 분할 대신 일자 단위 시간순 분할을 선택했나요?
2. 현재 모델 입력에 EOL 결과나 완료시간이 들어가면 어떤 문제가 생기나요?
3. 불량 Recall 80%를 달성해도 검토율이 30%를 넘으면 어떻게 판단하나요?
4. AP와 정확도는 서로 어떤 정보를 주나요?
5. 검사 셀을 늘리면 왜 합격률 자체는 변하지 않을 수 있나요?
6. 무한 버퍼를 유한 버퍼로 바꾸면 어떤 결론이 바뀔 수 있나요?
7. 모의 데이터 성능을 실제 현장 성능으로 주장할 수 없는 이유는 무엇인가요?
8. 모델의 기여도와 실제 불량 원인은 어떻게 다른가요?
9. Windows CPU 추론시간과 Jetson 추론시간을 비교하려면 어떤 조건을 맞춰야 하나요?
10. AI가 작성한 부분과 본인이 검증·변경한 부분을 어떻게 구분하나요?

## Jetson 검증 시 반드시 기록할 측정 범위

OS/Python 버전, 전원·클럭 모드, 모델 해시, 입력 수와 순서, warm-up 수, 반복 수, 중앙값/P95, 파일 입출력 포함 여부, 오류·거부 건수. 초기에는 센서를 흉내 낸 JSON 리플레이를 사용하고 실제 설비 연결 성과로 표시하지 않습니다.

## 선택 확장

실제 수업 측정 데이터를 사용할 수 있게 되면 별도 폴더와 데이터 계약을 만들고 계보·측정시점·레이블 획득을 확인합니다. 비전 AI는 현재 구현하지 않았습니다. 이미지와 정답을 확보한 뒤 별도 검증으로 추가하며 현 데이터에 이미지가 있다고 주장하지 않습니다. LLM은 근거 파일을 읽고 설명문을 작성하는 보조 단계부터 연결하고, 도구 실행과 근거 인용을 검증합니다.
