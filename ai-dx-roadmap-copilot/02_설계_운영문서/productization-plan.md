# 상용화를 목표로 한 제품화 계획

## 목표

이 프로젝트의 최종 목표는 경험용 데모가 아니라, 제조·에너지 기업의 DX 조직이 파일럿으로 도입할 수 있는 **AI/DX 과제 포트폴리오 의사결정 플랫폼**이다.

다만 현재 구현을 곧바로 상용 제품이라고 부르지는 않는다. 현재는 제품 가설과 의사결정 코어를 검증한 Phase 0이며, 아래 단계의 보안·운영·고객 검증을 통과해야 상용 후보로 승격한다.

## 제품 사용자와 가치

### 주요 사용자

- DX/DT 전략 담당자: 여러 과제를 비교하고 로드맵을 작성한다.
- 현업 과제 담당자: 문제·데이터·기대효과·담당자를 등록한다.
- 임원·심의 담당자: 근거와 KPI를 보고 파일럿·확대·중단을 결정한다.
- 운영·보안 담당자: 접근권한, 데이터 보존, 감사 이력을 관리한다.

### 제품이 해결할 문제

아이디어, 기술 트렌드, 현업 요청, 운영 데이터가 서로 다른 문서에 흩어져 있으면 DX 투자 판단이 사람의 기억과 발표자료에 의존한다. 제품은 이를 과제 카드·근거·점수·로드맵·KPI·승인 이력으로 연결한다.

### 제품 가치

1. 무엇을 먼저 추진할지 비교 가능한 기준 제공
2. 근거 없는 효과·목표·벤치마크의 자동 확정 방지
3. 파일럿 이후 실제 KPI와 의사결정 이력 연결
4. 조직·사업부·프로젝트가 바뀌어도 재현 가능한 운영 프로세스 제공

## 제품 흐름

```text
자료·업무요청 수집
  → 과제 카드 정규화
  → 출처·데이터 준비도 검증
  → 결정론적 우선순위 계산
  → 선택적 LLM 초안·요약
  → 근거·정책 게이트
  → 사람 승인
  → 파일럿 실행·KPI 측정
  → 확대·수정·중단 결정과 감사 기록
```

LLM은 제안자다. 점수 계산, 근거 존재 여부, 목표값 보류, 승인 상태 변경은 서버의 정책·검증 계층이 권한을 가진다.

## 단계별 목표

### Phase 0 — 현재 완료: 재현 가능한 의사결정 코어

- 합성 과제 카드
- 설명 가능한 가중치 점수
- 기존 포트폴리오 중복 제외
- KPI 기준값 보류
- 사람 검토 체크리스트
- 외부 API 없는 테스트와 리포트

판정: **포트폴리오용 MVP / 상용 아님**.

### Phase 1 — 기업 파일럿 후보

- 로컬 파일럿 저장소와 API 계약을 먼저 검증한 뒤 PostgreSQL 기반 영속 저장소와 스키마 버전 관리로 교체
- 조직·워크스페이스·사용자·역할 모델
- OIDC/SSO 연동 가능한 인증 경계와 RBAC
- CSV·Excel·문서 저장소·이슈관리 도구용 커넥터 인터페이스
- 원문·청크·출처·수집시각·해시를 보존하는 evidence store
- 과제 카드·심의·KPI 기준값을 제공하는 버전 API
- 사람 승인·반려·수정·위임과 불변 감사 이벤트
- 최소한의 웹 화면: 후보 목록, 점수 근거, KPI 보류 사유, 승인 대기
- 공개/합성 데이터로 전체 파일럿 시나리오 재현

현재 구현 범위: 로컬 파일 저장소, Bearer 개발 토큰, 테넌트·워크스페이스 경계, 실행·결정·KPI 기준값·감사 API, 멱등성·입력 경계·감사 무결성 검증, 근거 URL 입력·최소 웹 화면.

판정: 한 조직 또는 한 사업부에서 제한된 실제 데이터로 검토 가능한 **pilot candidate**가 되기 전 단계의 **local pilot skeleton**.

### Phase 2 — 운영 가능한 제품 후보

- 테넌트별 데이터 격리와 권한 테스트
- 비밀값 관리, 암호화, 보존기간, 삭제·내보내기 정책
- 입력 문서의 PII/민감정보 분류와 마스킹
- LLM provider 교체 가능 구조와 선택적 온프레미스 경로
- 구조화 출력·출처 인용·근거 부족 보류·prompt injection 방어 테스트
- 지연시간·비용·실패율·거부율·승인율 관측
- 백업·복구·마이그레이션·롤백·rate limit·장애 대응
- 회귀 평가셋과 릴리스 전 품질 게이트
- Docker 기반 배포와 운영 runbook

판정: 보안·운영 검토를 통과한 **production candidate**. 실제 SLA는 측정 전에는 주장하지 않는다.

### Phase 3 — 상용 서비스

- 고객 온보딩·테넌트 프로비저닝·사용량/비용 정책
- SLA와 지원 절차
- 보안·개인정보·계약·DPA·침투 테스트 등 고객별 요구사항
- 가격·라이선스·지원 모델
- 공식 문서, 장애 공지, 버전 호환성 정책

판정: 특정 고객의 계약·보안·운영 검토를 통과한 뒤에만 상용 서비스라고 표시한다.

## 상용 후보의 필수 품질 게이트

- 근거가 없는 과제·KPI·벤치마크는 `review_required` 또는 `insufficient_evidence`로 보류한다.
- 기준값이 없는 KPI의 목표값은 자동 생성하지 않는다.
- AI가 승인 상태, 예산, 담당자, 운영 전환을 직접 변경하지 않는다.
- 모든 점수·프롬프트 결과·사람 수정·승인·반려에 `runId`, 사용자, 시간, 버전, 근거를 남긴다.
- 동일한 입력·루브릭·버전으로 동일한 결정론적 점수를 재현할 수 있어야 한다.
- 외부 API 장애 시 안전한 fallback과 사용자에게 보이는 제한사항이 있어야 한다.
- 고객 데이터와 테스트 픽스처를 분리하고, 저장·전송 경계를 문서화한다.

## 상용화 판단의 정직한 표현

현재는 `offline_deterministic`, `synthetic_fixture`, `externalApiCalled=false`인 상태다. 따라서 현재 리포트는 제품 가설과 코어 검증의 증거이지, industrial-automation 내부 적용 성공이나 상용 서비스 운영 실적을 의미하지 않는다.
