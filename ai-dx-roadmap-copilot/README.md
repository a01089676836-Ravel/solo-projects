# industrial-automation DT AI/DX 과제 발굴·로드맵·성과관리 Copilot

industrial-automation DT 직무의 `DX 전략·로드맵`, `AI/Digital 혁신 과제 발굴·기획`, `AX 프로세스 최적화·거버넌스`, `AI/DX 트렌드·선진사 벤치마킹`을 하나의 재현 가능한 1인 프로젝트로 구현한다. 최종 목표는 경험용 데모가 아니라 기업 파일럿과 상용화를 검토할 수 있는 제품 후보이며, 현재는 오프라인 코어와 Phase 1 로컬 파일럿 골격까지 구현한 상태다.

프로젝트를 처음 보는 사람은 먼저 [프로그램 제작과정·선택이유 안내](00_처음읽기_프로그램제작과정_선택이유.txt)를 읽는다.
제품화 기준은 [제품화 계획](02_설계_운영문서/productization-plan.md)과 [제품 계약 초안](02_설계_운영문서/product-contract.md)에 기록한다.
[아주 쉽게 이해하기](02_설계_운영문서/plain-language-guide.md)와 [운영 runbook](02_설계_운영문서/operations-runbook.md)도 함께 참고한다.

## 폴더 안내

- `01_입력데이터_실행기록`: 합성 후보 데이터와 로컬 실행 기록
- `02_설계_운영문서`: 제품 정의, API 계약, 운영·복구·판단 기준
- `03_검증리포트_진행기록`: 데모 결과, 검증 결과, 전체 진행 기록
- `04_프로그램코드`: 점수·KPI·로드맵·서버 프로그램
- `05_자동검증테스트`: 코어·API·권한·감사·웹 동작 테스트
- `06_사용자화면`: 후보 입력, 결과 확인, 승인·KPI 입력 화면

## 현재 상태

- 제품화 단계: **Phase 0 완료 + Phase 1 local pilot skeleton / 상용 아님**
- 최종 제품 가설: 기업 DX 조직용 과제 포트폴리오 의사결정 플랫폼
- 오프라인 결정론적 코어 구현
- 합성 과제 카드 5개와 출처·사람 검토 지점 포함
- 설명 가능한 6개 항목 가중치 점수
- 기존 제조설비 Agent와 중복되는 후보 자동 제외
- 상위 후보별 KPI 초안 생성
- 기준값이 없으면 목표값을 만들지 않고 `baseline_required`로 보류
- 30/60/90일 구현 로드맵과 사람 승인 체크리스트 생성
- 웹 화면에서 30/60/90일 산출물과 단계별 사람 승인 지점 표시
- Phase 1 로컬 파일럿 API·저장소·Bearer 개발 인증·테넌트 경계·감사 이력·웹 화면
- viewer 읽기 역할과 reviewer/admin 쓰기 역할의 권한 경계 테스트
- production 환경에서 로컬 데모 토큰이 비활성화되는 경계 테스트
- 실행 생성 API의 `Idempotency-Key` 중복·충돌 검증과 로컬 재시도 안전성
- 후보·KPI·출처의 빈 값·길이·ID·URL 형식 경계 검증
- JSON 요청 형식 검사와 웹 보안 헤더(CSP·frame 차단·referrer 제한)
- 사람이 KPI 기준값과 측정 출처를 등록하는 파일럿 흐름
- 후보별 승인·반려·보류 상태와 판단 사유를 결과·감사 이력에 연결
- 감사 이벤트 해시 연결과 변조 감지 결과 API
- 추천 결과에서 근거 자료 제목·URL을 확인하는 출처 화면
- 사용자가 새 과제 후보를 입력해 샘플 후보와 같은 기준으로 비교하는 실행 흐름
- 사용자 입력 후보에 추가 공개자료 제목·URL을 연결하고 형식 검증하는 흐름
- Astra API는 아직 호출하지 않음

현재 상태를 상용 운영으로 표현하지 않는다. 실제 상용 후보가 되려면 영속 저장소, 인증·RBAC, 테넌트 격리, 데이터 커넥터, 감사 로그, KPI 기준값 수집, 보안·관측성·백업·복구·배포 검증이 추가로 필요하다.

## 실행

Node.js 22 이상, 현재 환경에서는 Node.js 24.19.0을 사용한다.

```powershell
cd .
npm.cmd test
npm.cmd run demo
npm.cmd run check
npm.cmd run verify
npm.cmd start
```

`npm.cmd run demo` 실행 결과는 `03_검증리포트_진행기록/demo-run.json`과 `03_검증리포트_진행기록/demo-run.md`에 저장된다. `npm.cmd run check`는 외부 API를 호출하지 않고 코어만 확인한다. `npm.cmd run verify`는 테스트·데모·코어 검사를 순서대로 실행한다.

전체 진행 과정·대안 비교·근거·검증 결과의 자세한 기록은 `03_검증리포트_진행기록/process-traceability.txt`에 있고, 처음 읽기용 요약본은 프로젝트 최상위의 `00_처음읽기_프로그램제작과정_선택이유.txt`에 있다.

`npm.cmd start`는 로컬 파일럿 서버를 `http://127.0.0.1:8766`에 연다. 브라우저에서 개발용 토큰 `local-demo-token`으로 샘플 과제를 실행하거나 새 후보를 입력해 비교하고, 승인 검토 이력을 남길 수 있다. 브라우저는 실행마다 `Idempotency-Key`를 자동 발급하며, 같은 요청 재전송은 중복 실행으로 저장하지 않는다. 개발용 파일 저장소는 `01_입력데이터_실행기록/실행기록/`에 생성된다. 실제 다중 사용자 운영 전에는 PostgreSQL·OIDC/SSO·RBAC으로 교체해야 한다.

## 예상 추천 순위

1. AI·DX 과제 발굴·우선순위·로드맵 Copilot
2. AX 업무 프로세스 최적화·거버넌스 Agent
3. AI/DX 트렌드·선진사 벤치마킹 Radar

스마트에너지 Digital Twin-lite는 회사 산업 적합도를 보여주는 시나리오로 남겨두되, 현재 DT 직무 직접 적합도 기준의 신규 프로젝트 Top 3에서는 4순위로 둔다.

## 다음 구현 단계

1. Phase 1: 로컬 파일럿 검증 후 PostgreSQL·워크스페이스·RBAC·감사 이벤트·버전 API로 교체
2. 현재 입력 후보 흐름을 공개자료 기반 출처 카드와 실제 업무 인터뷰 입력 양식으로 확장
3. 후보별 before/after 프로세스와 KPI 기준값 수집·승인 흐름 구현
4. 선택적으로 Astra 구조화 출력 어댑터를 붙이고 결정론적 루브릭과 차이를 비교
5. LLM이 근거 없는 목표나 벤치마크를 제안하면 보류하는 회귀·보안 테스트 추가
6. Docker·관측성·백업·복구·운영 runbook까지 검증한 뒤 pilot candidate로 승격

외부 API 연결 전에는 키를 이 폴더에 복사하지 않는다. live 호출 성공·모델 품질은 별도 검증 전까지 미확인으로 기록한다.
