# AI 업무 위임 기록

- 사용자 의도: 이전 작업을 재개하되 오늘 논의한 Opal·의도·경험 기준의 보완을 먼저 진행. 토큰 사용 최소화.
- Codex 담당: 기존 상태·코드 대조, 보완 문서, 작업자 UI와 피드백 저장, 관련 회귀 검증.
- 도구 선택 이유: 현재 작업공간의 파일 수정·실행·검증을 한 흐름으로 수행 가능. 다른 모델과의 품질 비교는 미실행.
- 경계: 기존 test 표본으로 튜닝하지 않음. Opal 실행·현장 성과·사용자 판단을 창작하지 않음.
- 수락 기준: validation 알림 목록·상세와 단위 표시, 빈 목록·API 실패 구분, 피드백의 검토 대기 저장, 재전송 중복 방지, 기존 사건 보존.
- 사용자 직접 검토: 화면의 판단 흐름과 문구가 도움이 되는지, 다음 단계의 실제 업무 목표. 아직 평가받지 않음.
- 구현·검증 결과: 최신 STATE.md 및 tests/feedback.test.mjs 참조.

## 2026-09-14 추가 위임 범위

- 사용자 요청: 실제 MES가 없다는 제약을 인정하고, 공정·설비·운전 상태가 데이터 해석에 미치는 영향을 확인하기 위해 `MES-lite`와 공개 다중 운전 모드 데이터 적용을 단계적으로 진행.
- Codex 담당: BaSyx의 공개 운전 모드·Digital Twin 개념과 공개 데이터 후보를 조사하고, 현재 Node 구조를 유지한 채 MES 문맥과 데이터 어댑터를 추가.
- 사람의 판단이 필요한 부분: 이 관점이 사용자의 원래 생각인지 대화 중 새로 채택한 것인지 소급 확정하지 않음. 최종 경험 정리는 사용자가 요청한 시점에 대화 기록과 실제 구현·검증 증거를 함께 보고 작성.
- 금지 범위: 화학공정·항공엔진 공개 데이터를 반도체 현장 데이터로 표현하지 않음. MES/Digital Twin을 실제 electronics-manufacturer 시스템에 적용했다고 주장하지 않음.

## 2026-09-14 시계열 판단 개선

- Codex 담당: TEP 행 단위 기준선 위에 persistence·모드 전환 보류를 추가하고, virtual MES benchmark 문맥과 비교 보고서를 연결.
- 선택 이유: 정상 점수 한 번의 초과와 운전 모드 변경 직후의 점수를 즉시 설비 이상으로 확정하면 운영 판단이 과민해질 수 있으므로, 관찰·보류 상태를 별도로 남김.
- 사람의 판단이 필요한 부분: persistence 행 수와 전환 유예 행 수는 실제 샘플링 주기·운전 규정으로 다시 정해야 함. 현재 3·2는 데모 검증 설정임.
- 실제 결과: 새 temporal·virtual MES 테스트 포함 `npm.cmd test` 45/45 PASS. TEP 정상 holdout의 mode-aware temporal 결과는 10/1,803 anomaly rows, 4 episodes이며 fault recall은 미측정.
- 추가 연결: `run-local-agent.ps1 -VirtualMes`로 가상 Work Order·Lot·Operation·운전 모드를 사건 문맥에 선택적으로 붙이고, Agent 입력 사실로만 전달한다. 안전 출력은 기존처럼 로컬 FSM이 결정한다.
- 할루시네이션 점검: `npm.cmd run agent:audit`를 추가해 5개 실제 로컬 실행과 악의적인 `e99` 근거 선택을 검사한다. 출력은 `reports/agent-grounding-audit.json`에 저장하며, 이는 코드 경계와 참조 일치 검사이지 현장 적합성 증명이 아니다.

## 사용자가 요청한 후속 산출물

- 순서: 최종 경험 정리 후 코드-의도 해설을 별도로 작성.
- 산출물: 코드만 읽어도 “왜 만들었는가, 무엇을 입력받고 어떤 결과물을 내며, 어디까지가 구현·검증됐는가”를 파악할 수 있는 코드-의도 해설.
- 범위: 실제 모듈·함수·입출력·데이터 흐름·로컬 FSM/Agent 권한 분리·SOP/fallback·MES-lite·TEP temporal 기준선과 실행 명령을 코드 근거에 연결한다. electronics-manufacturer 내부 시스템을 구현했다고 확대하지 않는다.
- 결과: 사용자의 시작 계기와 대화 중 구체화된 판단을 구분한 `docs/experience-summary.md`, 초보자용 코드 흐름을 정리한 `docs/code-intent-guide.md`를 생성했다.
